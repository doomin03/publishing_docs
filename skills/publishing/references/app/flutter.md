# 플랫폼: 앱 (Flutter)

입력(`mockup/`·`figma/`)과 무관하게 Flutter 로 옮길 때의 주의점이다.
근거가 모두 SportLog 실측이라 이름·경로는 `sportlog-case.md` 에 두고 여기는 일반형만 적는다.

## 목업 액자 바깥 — 안전영역

- 목업은 폰 액자 안이라 시스템 내비게이션 바가 없다. 하단 안전영역을 끈 화면에서
  하단 고정 버튼이 제스처 바 아래 깔렸다(`_rules` 「하단 시스템 UI」).
- 처리: 하단 안전영역을 켜거나, 고정물의 아래 위치에 기기 하단 인셋을 더한다. 스크롤 끝에도 인셋만큼 여백을 남긴다.
- 화면을 만질 때 하단 안전영역을 끈 자리를 먼저 찾는다.

## 한국어 줄바꿈

- 목업 CSS 는 단어 단위 줄바꿈(`keep-all`)인데 Flutter 기본은 한국어를 아무 글자에서나 자른다(`PUB-FLOW` §1-3).
- 값이 길어지는 행(이름·제목)에서 줄이 달라진다. 공용 행 컴포넌트에서 한 번 처리한다 — 화면마다 하면 흩어진다.

## 배율 단위

- 목업 px 을 설계 기기 기준 배율 단위로 옮긴다. 글자·모서리·정사각은 각자의 단위를 쓴다.
- 세로에 다른 배율을 섞으면 찌그러진다(`PUB-FLOW` §3). 토큰 파일 자체에는 배율을 붙이지 않는다(`_rules` 「값 쓰는 법」).
- 설계 기기 크기와 배율 라이브러리는 프로젝트마다 다르다 — SportLog 는 `sportlog-case.md`.

## 테마 배경

- 테마 배경을 루트에 한 겹 깔고 화면 바탕을 칠하지 않는 구조라면, 화면에서 불투명 바탕을 깔면 배경이 잘린다(`PUB-FLOW` §4-9).
- 테마가 없는 사용자의 기존 바탕(테마 값이 비어 있음)을 덮어쓰지 않는다(`PUB-FLOW` §4-9).

## 골든·시각 검증

- 골든은 OS 마다 렌더가 다르다. 기준선을 만드는 OS 를 하나로 정하고, 다른 OS 는 허용치로 비교한다(`ver4-publishing` §4).
- 기준선 갱신은 기준 OS 에서만 한다(`ver4-publishing` §4, `PUB-GOLDEN` 규칙).
- 골든 시험이 특정 OS 에서 skip 되면 그 OS 의 「초록」은 아무것도 검증하지 않은 것이다(`TRAPS` §21).
- 한 상태 = 골든 한 장. 이름에 화면과 상태를 함께 담는다(`PUB-GOLDEN` 규칙).
- 갱신한 png 는 눈으로 보고 커밋한다(`PUB-GOLDEN`, `ver4-publishing` §4).
- 앱을 웹으로 빌드해 녹화하는 방식은 얕은 화면만 된다. 네이티브 플러그인(카메라 등)을 타는 깊은 화면은
  웹에서 stub 이라 못 간다 — 「웹 녹화 불가」로 적고 통과로 쓰지 않는다(`style-workflow` §3-3·§6).

## 토큰·컴포넌트

- 토큰 클래스와 공유 위젯의 이름·자리는 프로젝트 고유다. SportLog 는 `sportlog-case.md`.
- 손으로 관리하는 토큰 클래스와 생성 토큰이 공존하면, 기존 클래스를 공개 API 로 두고 값만 생성물에서 파생하는
  안이 권고됐다(`style-workflow` §2). 결정은 프로젝트 몫이다.
