# Flutter 스타일 구조와 설계 입력

## 적용 문서 선택

| 프로젝트 상태 | 적용 문서 |
|---|---|
| 신규 앱으로 구조를 처음 잡는다 | [스타일 패키지형](flutter-style-package.md)으로 시작한다. 프로젝트에서 앱 내부 관리로 결정했다면 앱 내부형을 적용한다. |
| 이미 스타일 패키지나 공용 UI 패키지를 쓴다 | [스타일 패키지형](flutter-style-package.md)을 적용하고 기존 패키지의 공개 API와 생성 절차를 따른다. |
| 앱 내부에서 테마·토큰·공통 위젯을 관리한다 | [앱 내부 관리형](flutter-style-in-app.md)을 적용한다. |

기존 프로젝트는 앱과 패키지의 pubspec, MaterialApp의 테마 연결, 공용 위젯 import 경로부터 확인한다. 양쪽이 공존하면 변경할 토큰과 컴포넌트별로 소유 위치를 확인하고 기존 공개 경로를 사용한다.

## 설계 입력과 정본

프로젝트에 설계 문서가 있으면 그 위치를 사용한다. 신규 프로젝트의 기본 예시는 다음과 같다.

| 자료 | 저장 위치 예시 | 기록할 내용 |
|---|---|---|
| 화면과 상태의 기준 목록 | `docs/design/screens.md` | 화면·상태, 대상 폭과 변수 모드, Figma 프레임·버전 링크 또는 HTML 파일·리비전, 동작·예외, 적용 근거 |
| 토큰 입력과 대응 | `design/tokens/` | 승인된 변수 내보내기 파일 또는 출처 링크, 모드·별칭, 코드 토큰 대응과 갱신 절차 |
| 반응형 정책 | `docs/design/responsive.md` | 기준 논리 폭·높이, 폭 구간, 최대 콘텐츠 폭, 열 전환, 글자 스케일과 시스템 인셋 정책 |
| 검증 자료 | 프로젝트 테스트·골든 경로와 작업 기록 | 화면·상태별 캡처 조건, 승인된 구현 골든, 실측 수치, 확인한 OS와 사용자 행동 |

HTML과 Figma가 함께 있으면 [화면별 기준 판정](../common/source-precedence.md)을 따른다. 토큰 원본과 생성 코드는 프로젝트의 갱신 절차로 연결한다. 손으로 관리하는 코드가 원본인 프로젝트는 대응표에 코드 경로를 기록한다. 이미지·폰트 등 앱이 사용하는 자산은 소유 앱 또는 패키지에서 등록하고 등록 위치를 문서에 남긴다.

## 테마와 공통 위젯

다이얼로그·바텀시트·버튼의 외곽과 호출부 콘텐츠 분리, 태블릿 레이아웃 파일 구성은 [공통 UI와 태블릿 레이아웃](flutter-ui-composition.md)을 적용한다.

- 디자인 원본의 색·간격·타이포·모서리·그림자에서 역할 기반 토큰을 정의한다. 팔레트 원색과 표면·텍스트·오류 등 사용 역할을 구분한다.
- 표준 Material 스타일은 ColorScheme, TextTheme, AppBarTheme, 입력·버튼 테마에 매핑한다. 별도 역할 값은 기존 방식이나 ThemeExtension을 사용한다. 앱 루트에서 지원하는 테마와 ThemeMode를 조립한다.
- 여러 기능에서 같은 의미로 쓰는 버튼·입력·카드·빈 상태는 공용으로 두고, 화면 전용 문구·데이터·동작은 기능 경계에 둔다. 기존 공용 컴포넌트에 필요한 상태가 있으면 우선 재사용하고, 변형은 재사용 근거가 있을 때 추가한다.

## ScreenUtil과 반응형 레이아웃

- ScreenUtil이 있으면 앱 셸에서 초기화하는 위치와 활성 디자인 캔버스의 designSize를 확인한다. 신규 도입 시 기준 폭·높이, 글자 배율과 회전·창 크기 변경 시 갱신 정책을 먼저 문서화한다.
- 토큰은 배율 적용 전 설계 단위로 두고 렌더링 경계에서 한 번만 변환한다. .w는 프로젝트에서 폭 기반으로 정한 치수, .h는 높이 비례가 명시된 치수, .sp는 텍스트, .r은 두 축에서 균일한 크기가 필요한 곳에 적용한다. 기존 프로젝트에 별도 규약이 있으면 그 규약을 따른다.
- Flutter 레이아웃과 디자인 기준은 논리 픽셀로 맞춘다. 골든 PNG의 실제 픽셀 크기를 레이아웃에서 사용할 때는 캡처 배율을 확인한다. 시스템 인셋과 이미 측정한 레이아웃 크기는 현재 논리 단위로 사용한다. 기기 글자 확대를 포함해 줄바꿈과 오버플로를 확인한다.
- 태블릿 여부보다 LayoutBuilder의 가용 폭으로 레이아웃을 결정한다. 같은 구조에서 패딩·최대 폭만 바뀌면 한 위젯에 제약을 적용한다. 목록·상세가 나란히 표시되는 등 배치와 탐색이 달라질 때 compact/wide 위젯으로 분리하고 상태·데이터·콜백을 공유한다.
- 폰, 태블릿 세로·가로, 분할 화면, 중단점 전후를 검증한다. 큰 글자, 시스템 인셋, 키보드가 적용된 상태에서 주요 행동을 실행하고 [검증 체크리스트](../common/checklist.md)에 기록한다.
