# Flutter 스타일 패키지형

신규 프로젝트의 기본 구조와 기존 공용 UI 패키지를 쓰는 프로젝트에 적용한다. [설계 입력·테마·배율 공통 기준](flutter-style-architecture.md)을 함께 적용한다.

```text
docs/design/                      화면·상태·반응형 설계 문서
design/tokens/                    토큰 입력 또는 출처·대응 기록
packages/app_ui/
  lib/app_ui.dart                 소비 앱의 공개 import 경로
  lib/src/tokens/                 팔레트·역할·간격·타이포
  lib/src/theme/                  공용 테마와 컴포넌트 스타일
  lib/src/components/             도메인에 독립적인 공용 위젯
  test/                          공용 위젯 상태와 골든
apps/mobile/lib/
  app/                           앱 테마 선택·셸·배율·내비게이션
  features/                      화면과 화면별 반응형 위젯·상태
```

1. 소비 앱이 UI 패키지에 의존하도록 구성한다. 공통 위젯은 값·문구·콜백을 전달받아 렌더링하며 앱의 기능 상태, API와 라우트를 직접 읽지 않는다.
2. 공통 토큰·테마·폰트·아이콘은 각각의 소유 위치와 등록자를 정한다. 앱 루트는 테마 모드, 브랜드, 배율, 시스템 인셋과 화면 셸을 조립한다. 패키지 내부 구현은 공개 엔트리로 필요한 API만 내보낸다.
3. 공유 위젯의 활성·비활성·로딩·오류 등 제공 상태는 패키지 테스트에서 검증한다. 화면 배치, 테마 연결, 태블릿 분기와 사용자 흐름은 소비 앱에서 확인한다.

스타일 전용 모듈은 일반 Flutter 패키지로 구성하고, 네이티브 플랫폼 구현이 필요한 경우에 Flutter 플러그인 구조를 검토한다.
