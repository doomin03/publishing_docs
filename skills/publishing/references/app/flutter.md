# 플랫폼: Flutter

스타일 구조를 설정하거나 테마·토큰·공통 위젯·배율·태블릿 분기를 변경할 때 [Flutter 스타일 구조와 설계 입력](flutter-style-architecture.md)에서 신규·패키지형·앱 내부형에 맞는 문서를 선택한다.

- 대상 화면이 사용하는 테마, 공유 위젯, 레이아웃과 크기 단위를 확인한다. 설계 픽셀을 옮길 때 저장소의 스케일 정책과 논리 픽셀을 기준으로 한다.
- 실제 글꼴과 텍스트 스케일에서 긴 문구와 줄바꿈을 확인한다. 테마별 배경과 투명 레이어의 합성 결과를 대조한다.
- 골든 테스트가 있으면 저장소의 기기 크기, 폰트, OS와 기준선 갱신 방식을 따른다. 건너뛴 테스트는 미확인으로 기록한다.
- 플랫폼 플러그인이 관여하는 흐름은 지원되는 환경에서 확인한다. 대체 환경을 사용했다면 검증 범위를 기록한다.

## 앱바와 화면 구조

다이얼로그·바텀시트·버튼과 태블릿 레이아웃을 구현할 때는 [공통 UI와 태블릿 레이아웃](flutter-ui-composition.md)을 적용한다.

- 기존 앱 셸이 앱바·내비게이션을 관리하면 해당 확장 지점을 사용한다. 표준 고정 앱바는 셸 또는 Scaffold.appBar가 담당하고, 스크롤과 함께 접히는 앱바는 SliverAppBar 등 저장소의 스크롤 구조에 맞춘다.
- 본문에는 콘텐츠 스크롤을 맡기고, 고정 액션은 화면 레이아웃에서 배치한다. 시안을 한 장으로 옮겨 만든 구조에서도 앱바와 본문의 스크롤·뒤로가기 책임을 확인한다.

## 시스템 UI와 키보드

- iOS와 Android에서 상태 표시줄, 노치, 홈 인디케이터와 시스템 내비게이션 영역을 확인한다. 배경은 시안에 맞춰 확장할 수 있으며, 조작 요소에는 안전영역을 적용한다. 셸과 화면에서 인셋을 중복 적용하지 않도록 확인한다.
- 폼은 키보드가 열린 상태에서도 포커스된 입력칸과 오류 메시지에 접근할 수 있도록 필요한 스크롤을 제공한다. Scaffold의 키보드 리사이즈와 MediaQuery.viewInsets 적용 위치를 확인해 같은 인셋을 두 번 반영하지 않는다.
- 제출 버튼을 키보드 위에 계속 노출할지, 스크롤 또는 키보드 닫기로 접근하게 할지는 기존 사용자 흐름과 화면 명세를 따른다. 마지막 입력칸에서 입력·오류 수정·제출까지 확인한다.

## 검증 환경

- 가장 작은 지원 화면에서 긴 콘텐츠와 마지막 입력칸을 검증한다. 키보드 표시·닫기, 스크롤, 버튼 탭, 앱바와 OS 뒤로가기 결과를 확인한다.
- 위젯 테스트로 인셋 변화나 스크롤·포커스 조건을 재현하고, 실제 시스템 바·키보드·뒤로가기 동작은 영향받는 OS의 시뮬레이터·에뮬레이터 또는 실기기에서 확인한다. 실행 환경과 결과는 [체크리스트](../common/checklist.md)에 남긴다.
