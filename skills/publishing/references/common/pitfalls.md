# 함정

`TRAPS.md` 에 실측 근거가 있는 것만 옮긴다. 새 항목도 근거 문서와 절을 달아야 한다.
플랫폼 고유의 실측 사고는 `app/`·`mockup/` 에 따로 있다.

### 1. 같은 화면의 판정이 라운드마다 뒤집힌다
- 증상: 카드 배경 판정이 다섯 번 정정됐다.
- 원인: 아래 2~5 가 겹쳤다. 기준이 틀린 채로 고쳤다.
- 올바른 처리: 기준(스펙·토큰)을 먼저 확정하고 고친다. 「N차 정정」이 나오면 기준을 의심한다.
- 출처: `TRAPS` §21 서두, `ver4-publishing` §5.

### 2. 기준물에서 테마가 빠져 색이 다르게 굳었다
- 증상: 기준 스냅샷은 흰 카드, 살아 있는 목업은 반투명 카드.
- 원인: 테마 속성이 문서 최상위 요소에 붙는데 추출 도구가 그 요소를 고정 문자열로 써서 버렸다.
- 올바른 처리: 기준물 머리말에 테마가 적혀 있는지 본다. 빠졌으면 그 기준물로 판정하지 않고 재생성을 요청한다.
  테마 빠진 기준물로 쓴 과거 판정은 믿지 않는다.
- 출처: `TRAPS` §21 표 1행, `ver4-publishing` §2.

### 3. 원본 HTML 을 사람이 풀어 값을 틀렸다
- 증상: 같은 값을 읽을 때마다 다르게 읽었다.
- 원인: 한 장 대부분이 CSS 이고, 스타일 블록이 여러 겹이며, 덮어쓴 시트가 요소를 숨긴다.
- 올바른 처리: 브라우저 계산값 스펙만 읽는다. 스펙이 없거나 낡았으면 HTML 직독으로 대신하지 않는다.
- 출처: `TRAPS` §21 표 2행. 세부는 `mockup/html-input.md`.

### 4. 시각 검증이 한 플랫폼에서 조용히 건너뛰어졌다
- 증상: 아무도 검수하지 않았고 목업과 어긋난 채로 쌓였다.
- 원인: 골든 시험이 특정 OS 에서만 돌고 나머지에서는 skip 이었다. CI 도 없었다.
- 올바른 처리: skip 을 통과로 읽지 않는다. 작업 OS 에서도 기준선과 허용치 비교가 돌게 한다.
- 출처: `TRAPS` §21 표 3행, `_rules` 「골든으로 검수한다」. 앱 세부는 `app/flutter.md`.

### 5. 한 작업공간에 세션 둘
- 증상: 수정 0건으로 토큰만 대량 소모, 잠금 대기.
- 원인: 두 세션이 같은 파일(번역 리소스 등)을 서로 덮었다.
- 올바른 처리: 한 작업공간에 세션 하나. 붙기 전에 그 자리에 도는 에이전트가 없는지 본다.
- 출처: `TRAPS` §21 표 4행, `ver4-publishing` §5.

### 6. 두 문서가 서로 반대 문장을 정본처럼 적었다
- 증상: 「카드는 불투명」과 「반투명」이 각자 근거를 달고 공존했다.
- 원인: 각 문서가 한쪽 모드(테마 꺼짐/켜짐)만 보고 썼다.
- 올바른 처리: 문장이 아니라 그 모드의 계산값으로 판정한다.
- 출처: `TRAPS` §21 🔴 문단.

### 7. 기준물 재생성이 일부 화면에서 실패해 옛 기준물이 남는다
- 증상: 재생성 뒤에도 몇 화면은 옛 스냅샷이다.
- 원인: 끝나지 않는 애니메이션 때문에 헤드리스 렌더가 출력하지 못했다.
- 올바른 처리: 재생성 결과에서 실패한 화면을 확인하고, 그 화면의 기준물 날짜를 의심한다.
- 출처: `TRAPS` §21 「재생성 순서」.

### 8. 시험이 초록인데 화면이 사용자에게 열리지 않는다
- 증상: 화면·상태·API 가 다 있는데 운영자에게는 기능이 없었다.
- 원인: 시험이 프로덕션의 게이트 값을 시험에서만 참으로 덮어썼다.
- 올바른 처리: 시험이 프로덕션 값을 덮어쓰면 근거가 아니다. 화면을 여는 조건이 참이 되는 입력이 있는지 본다.
- 출처: `TRAPS` §17. 퍼블 고유는 아니나 검증 판정에 그대로 적용된다 — 적용 범위는 **추정**.
