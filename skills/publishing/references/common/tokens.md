# 토큰

값은 복사하지 않는다. 토큰 정의 파일의 자리와 이름 체계는 플랫폼 파일에 있다.

## 규칙

- MUST 색·간격·타이포·모서리·그림자는 토큰 이름으로 쓴다(`PUBLISHING` §2-3, `style-workflow` §3-2).
- 하드코딩이 필요해 보이면 **토큰이 없는 것**이다. 임의로 근사하지 않는다(`style-workflow` §5-3).
- 목업 수치는 근사하지 않고 그대로 옮긴다(`PUB-FLOW` §3).
- 기존 토큰·컴포넌트를 지우거나 이름을 바꾸지 않는다(`_rules` 「값 쓰는 법」).
- 있는 공통 컴포넌트를 먼저 찾는다. 없을 때만 새로 만들고 목록(레지스트리)에 올린다(`style-workflow` §3-2).
- 고정 크기는 최소로. 글자 길이로 늘어나는 자리는 최소 높이로 둔다(`PUB-FLOW` §3).

## 목업 이름 ≠ 토큰 이름

- 목업 변수와 토큰은 이름 체계가 다를 수 있다. SportLog 는 거의 겹치지 않아
  대응을 **값으로만** 잡았다(`PUBLISHING` §2-3).
- 값이 같다고 뜻이 같지는 않다. 후보가 여럿이면 사람이 고른다(`PUBLISHING` §2-3).
- 계산값 스펙이 색마다 「값이 같은 토큰 이름」을 달아 주면 그것을 후보로 쓴다(`spec-body`).
  후보가 여럿 붙어 있으면 화면의 맥락으로 고른다 — 예: 특정 화면 전용 토큰을 다른 화면에 쓰지 않는다
  (`ver4-publishing` §3, 사례는 `app/sportlog-case.md`).

## 토큰에 없는 값 — 프로젝트 결정

SportLog 안에서 두 정책이 시기별로 반대였다. 어느 쪽인지는 프로젝트가 정한다(`source-precedence.md` D5).

| 정책 | 출처 |
|---|---|
| 새 토큰을 임의로 만들지 않는다. 설계 문서에 적고 사람이 고른다 | `PUBLISHING` §2-3 |
| 목업 수치를 그대로 넣고, 없으면 퍼블 전용 토큰 파일에 **더한다** | `PUB-FLOW` §3(오너 지시로 위를 덮음), `_rules` |
| 「정본에 추가할 목록」으로 모아 보고한다 | `style-workflow` §3-2 |

- 새 이름을 더할 때는 다른 작업자와 이름이 겹치지 않게 한다.
  같은 목업 값을 서로 다른 이름으로 넣어 통합에서 충돌했다(`PUB-FLOW` §2-1, `_rules`).

## 토큰 정본은 하나

- 토큰 소스가 둘(손으로 관리 + 생성물)이면 반드시 어긋난다. 시작 전에 하나로 정한다(`style-workflow` §2).
