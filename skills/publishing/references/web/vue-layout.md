# Vue SCSS 구조와 반응형·적응형 구현

## 스타일과 설계 입력

- 화면별 기준은 프로젝트의 설계 기록에 남긴다. 화면·상태, 기준 폭·높이, HTML 또는 Figma의 버전, 테마, 좁은 화면에서의 배치·스크롤 규칙을 기록한다.
- 앱의 전역 SCSS 진입점을 하나 확인한다. 공통 변수 출력, reset·폰트, 레이아웃, 컴포넌트, UI 라이브러리 보정의 로드 순서와 CSS 우선순위를 확인한다. 기존 순서를 수정할 때 관련 화면을 함께 검증한다.
- Sass 변수·맵은 중단점과 상태 스타일 생성 같은 빌드 시점의 값에 사용한다. 테마에서 바뀌는 의미 기반 색·간격·타이포는 전역 진입점에서 CSS 변수로 한 번 출력하고, 화면은 해당 값을 소비한다. 특정 테이블 행 높이처럼 지역 값은 컴포넌트 범위에 둔다.
- 반복 선언은 mixin으로 묶고, 버튼·입력·다이얼로그처럼 마크업과 상태를 공유하면 Vue 컴포넌트로 만든다. 공통 컴포넌트는 스타일과 상호작용 기본값을 제공하고, 호출부는 props·slots·events로 문구·콘텐츠·업무 동작을 전달한다.
- Element Plus를 사용하면 공용 스타일에서 지원되는 CSS 변수나 래퍼를 활용한다. 포털로 렌더되는 다이얼로그·팝오버는 실제 DOM에서 테마 범위와 포커스 이동을 확인한다.

## 반응형과 적응형 선택

| 조건 | 구현 방법 |
|---|---|
| 같은 구조에서 열 폭, 여백, 줄바꿈만 바뀜 | 유동 크기와 Grid/Flex를 사용한다. |
| 화면 폭보다 카드나 패널의 실제 가용 폭이 중요함 | 컴포넌트의 부모를 기준으로 컨테이너 쿼리 또는 레이아웃 제약을 적용한다. |
| 열 순서, 탐색 방식, 정보 그룹이 달라짐 | 넓은·좁은 레이아웃을 각각 정의하고 중단점에서 전환한다. |
| 고정 화면에서 가로·세로 공간이 모두 한정됨 | 전용 뷰포트 레이아웃에서 폭·높이·방향을 함께 검증하고 패널별 축소·스크롤 정책을 정한다. |

### 반응형 적용

1. 디자인 기준 폭에서 시작해 콘텐츠가 넘치거나 조작하기 어려워지는 지점을 실제 브라우저에서 확인한다.
2. Grid/Flex와 유동 단위를 사용한다. 줄어들어야 할 Grid/Flex 자식에는 필요한 경우 `min-width: 0`, 세로 패널에는 `min-height: 0`을 적용한다. 이미지·지도·영상은 `aspect-ratio`로 비율을 유지한다.
3. 입력·버튼·글자는 최소 사용 크기와 브라우저 확대를 검증한다. 일반 페이지는 자연스러운 세로 스크롤을 허용하고, 넓은 표처럼 독립적으로 스크롤할 영역은 해당 컨테이너에서 처리한다.

```scss
.panel-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 18rem), 1fr));
  gap: var(--space-panel);
}

.panel-grid > * { min-width: 0; }
```

### 적응형 적용

1. 넓은·좁은 화면별로 열 배치, 순서, 메뉴 방식, 고정 액션을 정한다. 중단점은 지원 화면과 콘텐츠 제약에서 도출해 프로젝트의 중단점 정의에 기록한다.
2. DOM 순서와 사용자 흐름이 같으면 CSS 미디어 쿼리로 열과 배치를 전환한다. 시각적 순서를 바꿨다면 키보드 포커스 순서도 확인한다.
3. 넓은 화면이 목록·상세를 나란히 보여주고 좁은 화면이 단계별 탐색을 제공하는 경우처럼 구조나 상호작용이 달라지면 `WideLayout.vue`와 `CompactLayout.vue`로 분리한다. 데이터 조회, 선택 상태, 폼 입력, 업무 콜백은 공통 상위 화면에서 관리한다. CSS와 JS가 같은 전환 조건에 의존하면 조건이 어긋나지 않도록 관리한다.
4. 고정 뷰포트는 모니터링 화면처럼 스크롤 정책이 별도로 지정된 경우에 적용한다. 폭·높이 중 먼저 제한되는 축으로 콘텐츠를 맞추고, 지도 위 마커는 이미지 기준 상대 좌표를 사용한다. 실제 크기를 읽어야 할 때만 ResizeObserver를 쓰고 해제 시 정리한다.

## 검증

- 기준 폭, 중단점 바로 아래·위, 작은 가로 화면, 세로 화면, 브라우저 확대에서 레이아웃을 확인한다. 고정 화면은 높이 제약을 별도로 재현한다.
- 긴 텍스트, 빈 목록, 오류 상태에서 넘침·잘림을 확인한다. 화면 크기가 바뀌어도 선택·입력값·주요 액션을 유지하는지 검증한다.
- 표·패널 내부의 스크롤, 고정 헤더·액션, 다이얼로그의 포커스 순서를 실제로 조작해 확인한다. 팀의 시각 회귀 도구 또는 [검증 체크리스트](../common/checklist.md)에 화면·상태·뷰포트를 기록한다.
