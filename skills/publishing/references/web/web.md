# 플랫폼: 웹

입력(`mockup/`·`figma/`)과 무관하게 웹으로 옮길 때의 주의점 자리다.
**웹 퍼블리싱의 실측 근거가 아직 없다.** 지어내지 않고 채울 항목과 질문만 둔다.
공통 규칙(`common/`)은 그대로 적용된다.

## 근거로 쓸 수 있는 단서 (확인 필요)

SportLog `style-workflow` 가 웹 스택을 짧게 언급한다. 대상 프로젝트에 맞는지 확인한 뒤에만 옮긴다.

- 웹 토큰의 주인은 손으로 관리하는 SCSS 토큰 파일이고, 컴포넌트는 거기서 나온 CSS 변수와
  UI 라이브러리 변수만 참조했다(`style-workflow` §2). 자리·책임 분리 문서는 저장소 `docs/guide/publishing/10-WEB-STYLE.md`.
- 시각 검증은 빌드 → 프리뷰 → 브라우저 스텝 녹화였다. 스텝은 화면 설계서의 흐름을 옮긴 것이고,
  단순 경로 방문만으로는 동선이 검증되지 않는다(`style-workflow` §3-3).
- 웹 단위 시험이 적어 「시험 통과」가 안전을 뜻하지 않았다. 시각 게이트가 사실상 유일한 안전망이었다(`style-workflow` §6).
