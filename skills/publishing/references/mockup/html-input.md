# 입력: HTML 목업

앱·웹 공통이다. 플랫폼별 옮기는 법은 `app/`·`web/` 에 있다.

## 원본 HTML 을 읽지 않는다 (MUST)

- 읽는 것은 **브라우저 계산값 스펙**이다. 화면당 수 KB 의 트리로,
  요소마다 위치·크기와 실제로 적용된 값이 적혀 있다(`TRAPS` §21, `PUBLISHING` 서두).
- 스펙이 없거나 낡았으면 HTML 직독으로 대신하지 MUST NOT. 재생성을 요청한다(`ver4-publishing` §1).
- 스펙 생성기는 이 저장소 `tools/mockup-spec/` 으로 옮기는 중이다. 실행법·출력 자리는 그쪽 문서가 정본이다.
- 목업 폴더를 통째로 검색하지 않는다. 번들 JS·3D 자산이 결과를 덮는다(`TRAPS` §21 「재생성 순서」).

## 계산값 스펙 읽는 법

형식은 `spec-body` 를 따른다.

- 머리말: 원본 파일, 계층(layer)·뷰, **테마**, 폰트 로드 여부, 문서 높이.
  - 테마 줄이 판정의 전제다. 테마가 비어 있으면 그 스펙으로 색을 판정하지 않는다(`TRAPS` §21).
  - 폰트가 로드되지 않았으면 줄바꿈·너비가 대체 글꼴 기준이다(`PUBLISHING` §1 「글꼴을 묶는다」).
- 한 줄: `선택자 [x,y w×h] 속성들 「문구」`. 들여쓰기는 포함 관계, `×N` 은 같은 모양 반복이다.
- 색 뒤의 `=이름` 은 **값이 같은** 토큰 이름이다. 후보이지 정답이 아니다(`common/tokens.md`).
- `@NN%` 는 투명도다. 반투명 판정은 이 값으로 한다.

## 왜 직접 읽으면 틀리는가 (기록)

계산값 스펙이 기계적으로 해결하는 것들이다. 스펙 없이 판정해야 하는 예외 상황에서만 참고한다
(`_rules` 「값을 읽는 법」, `PUB-FLOW` §3).

1. 같은 선택자가 여러 번 나온다. 뒤가 이기고 `!important` 는 더 이긴다.
2. 숨김(`display:none`)은 어느 선택자에 걸렸는지까지 본다.
   추출 도구가 넣은 숨김은 디자인이 아니다. 비슷한 이름의 다른 화면 규칙을 착각해 요소를 통째로 뺀 사고가 있었다.
3. `:root` 선언은 값이 아니다. 그 화면이 실제로 그리는지 확인한다.
4. 바탕과 카드는 다른 이야기다. 바탕은 테마 배경이 비치게 두는 경우가 있고, 카드는 계산값 그대로다.
5. 렌더로 확인하지 않은 것은 끝난 게 아니다.

## Figma 적용 시트가 덮인 HTML

- HTML 목업 위에 Figma 결과를 CSS 시트로 덮은 경우가 있다.
  그 시트가 DOM 의 절반을 숨기고, 색을 규칙 안에 직접 박는다(`design-4.0` §4.0·§4.2).
- DOM 만 읽으면 숨겨진 요소를 구현하라고 읽히고, 실제 배치(예: 목록이 아니라 격자)를 놓친다(`design-4.0` §4.0).
- 박힌 색은 목업 변수 표에 없으므로 토큰 대응표에도 없다. 「토큰 없음」으로 따로 모은다(`design-4.0` §4.2).
- 계산값 스펙은 시트가 적용된 뒤의 렌더다 — 그래서 위 문제를 피한다. **추정**(스펙 생성 방식에서 유도).
- 이 경우와 별도 Figma 파일이 함께 있으면 `common/source-precedence.md`.

## 정지 스냅샷의 한계

- 상태 한 장만 담는다. 문구 집합·상태 집합의 정본은 살아 있는 목업과 그 스크립트다(`PUBLISHING` §3, `design-4.0` §4.1).
- 상태 목록은 상태 원장에서 읽는다. 원장이 생성물이면 손으로 고치지 않는다(`PUB-STATES` 서두).
- 경로가 없어 추출이 닿지 않는 오버레이·토스트는 살아 있는 목업을 띄워 대조한다(`PUBLISHING` §6).
