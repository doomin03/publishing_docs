# 끝 조건과 결과 해석

명령·도구 이름은 플랫폼 파일에 있다. 여기는 뼈대다.

## 끝 조건 — 전부 통과해야 완료

- [ ] 그 화면의 **상태·상세 전부**를 했다. 진입 화면만 하고 닫지 않는다(`PUB-STATES` 규칙).
- [ ] 상태마다 시각 기준(골든·스크린샷) 한 장이 있다(`PUB-GOLDEN` 규칙 「한 상태 = 골든 한 장」).
- [ ] 갱신한 그림을 **눈으로** 보고 목업과 나란히 대조했다(`PUB-GOLDEN`, `ver4-publishing` §4).
- [ ] 문구를 텍스트로 뽑아 diff 했다(`PUBLISHING` §4).
- [ ] `judgement.md` 의 「본다」를 전부 봤다.
- [ ] 하드코딩된 색·간격·타이포가 새로 늘지 않았다(`style-workflow` §4-④).
- [ ] 작업 전에 돌린 기준선 대비 **실패가 늘지 않았다.** 그 화면 시험만이 아니라 전체를 돌렸다(`PUB-FLOW` §5).
- [ ] 기능(라우트·상태·API·값의 흐름)을 바꾸지 않았다. 바뀌었으면 커밋을 나눈다(`style-workflow` §3-6).
- [ ] 아래 어긋남 표를 남겼다. 없으면 「없음」이라고 쓴다.
- [ ] 확인하지 못한 것은 「미확인」으로 적었다. 통과로 쓰지 않는다(`style-workflow` §3-3·§6).

## 어긋남 보고 — 한 줄에 하나

목업과 Figma(또는 정본끼리)가 다를 때마다 한 줄을 남긴다. 판정 근거는 `source-precedence.md`.

| 화면 | 항목 | 목업값 | Figma값 | 선택한 쪽 | 사유 |
|---|---|---|---|---|---|

- 「사유」에는 `source-precedence.md` 의 표 번호나 사람의 판정(누가·언제)을 쓴다.
- 판정이 없으면 「선택한 쪽」을 「보류」로 두고 묻는다.

## 결과 해석

| 상황 | 판정 | 출처 |
|---|---|---|
| 작업한 화면이 시각 비교에서 달라짐 | 정상. 단 사람이 차이 그림을 보고 확인한다. 자동 통과 금지 | `style-workflow` §4 |
| 작업하지 않은 화면이 달라짐 | 회귀. 토큰·공유 컴포넌트가 남을 깼다. 멈추고 고친다 | `style-workflow` §4 |
| 화면이 사라짐 | 무조건 실패 | `style-workflow` §4 |
| 기준선이 없음 / 시험이 건너뛰어짐 | 판정 불가. 통과로 쓰지 않는다 | `style-workflow` §4, `TRAPS` §21 |
| 미세한 글꼴 렌더 차이 | 허용치로 흡수. 허용치는 설정/환경에 따라 다르다 | `style-workflow` §4, `ver4-publishing` §4 |
| 동적 콘텐츠(시각·난수) | 명시적으로 제외하고 사유를 적는다. 조용히 무시하지 않는다 | `style-workflow` §4 |
| 시험이 초록인데 화면이 안 열림 | 시험이 게이트 값을 덮어썼는지 본다 | `TRAPS` §17 |
