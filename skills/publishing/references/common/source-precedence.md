# 화면별 기준 판정

요청에서 지정한 기준과 대상 저장소의 승인된 설계·기획·토큰 정책을 확인한다. 프로젝트별 판단은 해당 프로젝트 문서나 작업 기록에서 관리한다.

| 결정 | 적용 방법 |
|---|---|
| D1 비주얼 충돌 | 화면·상태·플랫폼별로 지정된 기준을 적용한다. HTML과 Figma에 공통 순위를 부여하지 않는다. |
| D2 속성별 기준 | 구조·문구·비주얼·동작·토큰을 구분한다. 속성별 기준이 합의돼 있으면 적용 범위와 근거를 기록한다. |
| D3 한쪽에만 있는 상태 | 요청 범위에 속하고 승인된 자료에 있으면 그 자료를 사용한다. 나머지 자료의 미표기는 누락으로 기록한다. 승인이나 범위가 불분명하면 보류한다. |
| D4 Figma 기준 | 지정 프레임과 버전을 확인한다. [Figma 입력](../figma/figma-input.md)을 따른다. |
| D5 토큰 불일치 | [토큰 정책](tokens.md)을 따른다. |
| D6 결정권과 기록 | 합의된 기준은 구현자가 적용하고, 근거가 충돌하거나 기능·정책 결정이 필요하면 프로젝트 결정권자에게 확인한다. 기존 작업 기록 또는 작업 결과에 근거를 남긴다. |

1. 화면·상태·플랫폼·테마·폭이 일치하는지 확인한다. 비교 조건이 다르면 각각의 조건을 기록한다.
2. 출처가 하나여도 요청 범위와 적용 근거가 확인된 항목은 진행한다.
3. 값이 다르면 [보고 형식](checklist.md)에 적는다. 기준이 불명확하면 영향을 받는 항목만 보류하고 독립 작업을 진행한다.
4. 접근 실패, 자료 미표기, 명시적 삭제를 구분한다. 기존 요소나 동작 삭제에는 별도 근거가 필요하다.
