# 검증과 결과 기록

- [ ] 범위에 포함된 화면·상태를 확인하고 보류·미확인 항목을 표시했다.
- [ ] 관련 상태를 렌더링해 승인된 자료와 대조했다. 가능하면 문구를 추출해 비교했다.
- [ ] 프로젝트의 토큰·컴포넌트 규칙을 적용하고 요청 범위 밖의 기능 동작을 유지했다.
- [ ] 실행한 테스트, 시각 검증 환경과 결과를 남겼다. 건너뛴 시험과 확인할 수 없는 화면은 미확인으로 표시했다.
- [ ] 변경 범위 밖에서 발생한 시각 차이는 영향을 확인했다.

## 구조와 사용자 동작

변경 범위에 해당하는 항목을 확인한다. 화면별 동작 결정은 프로젝트의 화면 명세나 티켓에 남긴다.

- [ ] 공용 앱바·헤더, 본문 스크롤과 고정 액션의 역할을 코드에서 확인했다.
- [ ] 작은 지원 화면에서 시스템 UI 또는 키보드가 떠도 주요 콘텐츠와 액션에 접근할 수 있다. 앱은 영향받는 OS별로 확인했다.
- [ ] 화면의 주요 흐름을 실제로 실행했다. 폼이라면 마지막 입력칸 포커스 → 입력 → 오류 확인·수정 → 제출까지 확인했다. 실패·재시도, 닫기·뒤로가기는 해당하는 경우 검증했다.
- [ ] 검증한 OS·기기 또는 뷰포트, 사용자 행동, 기대 결과와 실제 결과를 기록했다. 실행하지 못한 항목은 이유와 함께 미확인으로 표시했다.

## 불일치 기록

| 화면·상태·조건 | 항목 | HTML 목업값·출처 | Figma값·출처 | 선택한 쪽 또는 보류 | 사유·결정 근거 |
|---|---|---|---|---|---|

한쪽에 표시가 없으면 미표기, 접근할 수 없으면 미확인으로 기록한다. 승인된 기준이나 결정자가 있으면 사유에 남긴다. 기존 작업 기록을 우선 사용하고, 정해진 위치가 없으면 작업 결과에 포함한다.

## 자동 비교

프로젝트에 기존 시각 검증이 있으면 해당 실행 절차를 따른다. PNG와 실측 수치 JSON을 비교할 때는 [퍼블리싱 검증 도구](../../../../tools/publishing-verify/README.md)를 사용한다. 화면·상태와 캡처 조건을 기록하고 보고서의 차이와 미확인 항목을 검토한다.
